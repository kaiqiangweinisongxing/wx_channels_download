# minib 支持指定 Device（PC / Mobile）模拟视口

## 现状与根因

minib 视口相关值全部硬编码且互不联动：
- `pkg/minib/page.go:2464-2467` — `screen`/`innerWidth`/`innerHeight` 固定 1440×900、`devicePixelRatio=2`
- `pkg/minib/page.go:2657-2659` — `matchMedia` 是 stub，只对含 `hover`/`pointer` 的查询返回 true，宽度查询（如 `(min-width: 768px)`）永远 false
- `pkg/minib/cssom.go:1150` — CSS 媒体查询按硬编码 1440 匹配，与 `innerWidth` 不联动
- `navigator.platform`/`maxTouchPoints`（page.go:2451/2460）固定桌面 Mac 特征，无任何 device 配置入口

## 已确认的决策

1. **零值（不传 Device）保持现状**：1440×900、MacIntel、dpr 2 —— 现有 scraper 调用方零改动
2. **DevicePC**：视口 **1080×880**
3. **DeviceMobile**：视口 **390×844**（iPhone 12-15 逻辑分辨率，dpr 3，竖屏）
4. **Mobile 联动移动 UA**：调用方未显式传 User-Agent 时自动使用 iPhone 移动端 UA 并移除桌面特征头；显式传 UA 时不覆盖

## 实现步骤

### 1. 新增 Device 类型与设备档案（pkg/minib/page.go）

```go
type Device string

const (
    DevicePC     Device = "pc"     // 1080×880, dpr 2, MacIntel, maxTouchPoints 0
    DeviceMobile Device = "mobile" // 390×844, dpr 3, iPhone, maxTouchPoints 5, coarse pointer
)

type device_profile struct {
    viewport_width, viewport_height int
    screen_width, screen_height     int
    screen_avail_width, screen_avail_height int
    pixel_ratio                     int
    platform                        string
    max_touch_points                int
    coarse_pointer                  bool
    user_agent                      string // 仅 mobile 使用
}
```

- `device_profiles` 表：PC 与 Mobile 两项；Mobile 的 UA 复用 clawreq `ProfileSafariIOS` 同款 iPhone Safari 16 UA
- 零值 `Device("")` 不在表中，由 resolve 函数返回 **legacy 档案**（完全复刻当前硬编码：1440×900、availHeight 875、MacIntel、touch 0），保证向后兼容

### 2. NavigateOptions 增加 Device 字段（page.go:58）

```go
// Device simulates a device class for viewport metrics, media queries,
// matchMedia, and touch fingerprint. Zero value keeps legacy 1440x900.
Device Device
```

- `validate_navigate_options`（page.go:393）增加校验：只允许 `""` / `pc` / `mobile`，其他值报错
- `pool.go` 的 `NavigateJob.Options` 与 `minib.go:440` Click 路径复用 `NavigateOptions`，自动透传，无需改动

### 3. page_runtime 挂载档案（page.go:273 / 1163）

- `page_runtime` 增加 `device device_profile` 字段
- `execute_page`（page.go:1163）构造时从 `page.navigate_options.Device` resolve 填充（两处 Page 构造均已保存 `navigate_options`，page.go:480/605）

### 4. install() 用档案替换硬编码（page.go:2447-2467）

- `navigator.platform`、`navigator.maxTouchPoints` ← 档案
- `screen` map（含 availWidth/availHeight）、`innerWidth`、`innerHeight`、`devicePixelRatio` ← 档案
- `navigator.userAgent` 无需改动：它取自本次文档请求头（page.go:1204），由步骤 6 的 UA 联动自动变为移动 UA

### 5. 统一媒体查询匹配（matchMedia + CSS 级联共用）

**cssom.go**：把 `media_width_matches`（cssom.go:1158）扩展为 `media_query_matches(query, viewport_width, viewport_height, coarse_pointer)`：
- 现有 `min-width`/`max-width` 逻辑保留，新增 `min-height`/`max-height`
- 新增 `orientation: portrait|landscape`（比较宽高）
- 新增 `hover: hover|none`、`pointer: fine|coarse`（由 `coarse_pointer` 决定，修复移动端误判）
- 支持以 ` and ` 连接的组合条件（当前组合宽度查询因解析失败恒为 true）
- **未识别特性保持各自现状语义**（评估器返回 "是否识别 + 是否匹配"）：CSS 级联路径未识别 → true（保持 `(prefers-color-scheme: dark)` 等现有行为），matchMedia 路径未识别 → false（保持 `prefers-*` 现有行为，避免影响动画门控）

**cssom.go:1150**：`css_media_matches` 改用 `runtime.device.viewport_width`（零值档案即 1440，行为不变）

**page.go:2657 matchMedia**：`matches` 改为调用共享匹配逻辑（替换现在的 `strings.Contains(query, "hover")`），返回的 map 形状与 no-op listener 方法保持不变

### 6. Mobile 联动移动 UA（page.go:433-437 及 POST 导航路径）

新增辅助函数，在 GET（`navigate`，page.go:434 合并调用方 headers 之后）与 POST 导航两处调用：

```go
func apply_device_user_agent(document_headers, caller_headers http.Header, device Device)
```

- `device == DeviceMobile` 且调用方 headers 未设置 User-Agent 时：
  - `document_headers.Set("User-Agent", iPhone Safari UA)`
  - 删除 `Sec-Ch-Ua` / `Sec-Ch-Ua-Mobile` / `Sec-Ch-Ua-Platform`（iOS Safari 不发送这些头）

### 7. 测试（新文件 pkg/minib/device_test.go，沿用现有 httptest 风格）

1. 零值：`innerWidth===1440`、`screen.width===1440`、dpr 2 —— 回归保护
2. `DevicePC`：`innerWidth===1080`、`innerHeight===880`；`matchMedia("(min-width: 768px)").matches===true`、`(max-width: 1079px)===false`
3. `DeviceMobile`：`innerWidth===390`、dpr 3、`maxTouchPoints===5`、platform==="iPhone"；`(orientation: portrait)===true`、`(hover: hover)===false`、`(pointer: coarse)===true`
4. CSS 级联联动：`@media (min-width: 1000px)` 规则在 PC 下生效、Mobile 下不生效（getComputedStyle / 渲染结果断言）
5. UA 联动：测试服务器回显请求头，Mobile 下文档请求 UA 为 iPhone；调用方显式传 UA 时不被覆盖；`navigator.userAgent` 跟随
6. 非法 Device 值 → Navigate 返回错误

## 明确不做（超出范围）

- `clientWidth`/`getBoundingClientRect` 等元素几何仍是合成值（minib 无布局引擎）
- `window.outerWidth`、`screen.orientation`、`visualViewport`、resize 事件派发 —— 当前不存在，不新增
- clawreq TLS 指纹仍为 Chrome（仅文档请求头层面模拟移动端）

## 涉及文件

- `pkg/minib/page.go` — Device 类型、档案、NavigateOptions、runtime 字段、install()、matchMedia、UA 联动、校验
- `pkg/minib/cssom.go` — 媒体查询匹配共享化与扩展
- `pkg/minib/device_test.go` — 新增测试
